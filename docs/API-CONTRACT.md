# Vitality Gym web — implementation contract

New, self-contained app. TypeScript + React/Vinext; Cloudflare D1 SQL; R2 files. UI pt-BR, currency BRL in integer cents, dates ISO and display America/Sao_Paulo. One gym/unit. Browser only: no Student Portal in this release. Domain entities and theme are server persisted. Default login identifier is exactly davibrandzoletti11@gmail (not an email to send mail to), initial password is generated into the local ignored environment file for new installations; existing account credentials are preserved. A .com alias is not invented.

## HTTP conventions
GET /api/health public; GET /api/branding public only safe visual keys; GET /api/me -> {user, csrfToken, settings}; POST /api/login {login,password,otp?} -> {user, csrfToken, settings}; POST /api/logout; POST /api/password {currentPassword,newPassword}; cookie HttpOnly SameSite Strict, Secure when HTTPS. Mutations require X-CSRF-Token plus Origin validation (login checks Origin only). JSON errors {error:string, code?:string, fields?:Record<string,string>}, actual HTTP status. JSON writes size capped. No tokens in localStorage. User = {id,name,login,role,active,permissions:string[],mustChangePassword?:boolean}. Role enum super_admin, admin, manager, reception, finance, trainer, personal. Server authorizes every route; trainer/personal scoped to assigned students.

## Domain handler
Backend exports async handleDomain(request: Request, url: URL, db: D1Database, actor: Actor): Promise<Response | null>. Actor defined/imported from server/auth.ts = {id,name,login,role,active,permissions:string[]}. Use JSON responses. No auth/CSRF in domain; API wrapper handles that. Backend exports `seedDemo(db, adminId)` from server/seed.ts, idempotent, optional env flag ENABLE_DEMO_DATA true; bootstrap root seeds admin + settings singleton. Demo records explicitly synthetic.

## APIs all under /api
GET /options -> {students:[{id,name,trainer_id?}],plans:[{id,name,price_cents,duration_months}],users:[{id,name,role}],exercises:[{id,name}],products:[{id,name,price_cents,stock}],suppliers:[{id,name}],classes:[{id,name,starts_at,capacity}]} scope and permissions apply. Limit 1000 options with server validation; list routes paginated.
GET /dashboard?days=30 -> {metrics:{activeStudents:number,monthlyRevenue:number,openInvoices:number,todayAttendance:number,overdueAmount:number,occupancy:number},revenue:[{date:string,revenue:number,expenses:number}],attendance:[{date:string,count:number}],planDistribution:[{name:string,value:number}],recentActivity:Audit[],upcomingClasses:Class[],pendingInvoices:Invoice[]}. Monetary metrics in cents.
GET /:entity?q=&page=1&pageSize=20&status= (max 100) -> {data:Record[],total,page,pageSize}. POST /:entity body -> record. PATCH /:entity/:id with version -> record (409 stale). No hard delete; archival state via patch/action. GET /:entity/:id -> record details/history if applicable.
Entities: students, staff, plans, memberships, invoices, expenses, exercises, workouts, assessments, classes, products, suppliers, purchases, sales, leads, notifications, users (root handles users), audit (read only), attendance (read only), access-events (read only).
POST /memberships/:id/renew {version} creates next period + invoice preserving contracted price; POST /memberships/:id/suspend or /cancel {reason,version}. Invoice autogenerated on membership creation.
POST /invoices/:id/pay {method:'pix'|'cash'|'card'|'transfer',version, idempotencyKey} full payment only. POST /invoices/:id/refund {reason,version,idempotencyKey}. Refund retains history; POST /invoices/:id/cancel {reason,version} if unpaid.
POST /attendance/check-in {student_id,override_reason?} checks active membership + configurable grace (3 days default), unique open entry; denied attempts recorded. POST /attendance/:id/check-out closes open entry.
POST /workouts/:id/activate {version}; workouts have items:[{exercise_id,day,sets,reps,load,rest_seconds,notes}] snapshot/version history; exercise names shown in responses.
POST /classes/:id/book {student_id}; POST /classes/:id/unbook {student_id}; capacity enforced atomically. GET /classes/:id includes bookings.
POST /products/:id/adjust {quantity,reason,version}; stock cannot go negative.
POST /purchases/:id/receive {version}; purchase items [{product_id,quantity,unit_cost_cents}], receipt atomic idempotent by status.
POST /sales/:id/refund {reason,version}; sale items [{product_id,quantity,unit_price_cents}], sale creation commits stock and ledger atomically.
POST /leads/:id/convert {version} creates student and records link; idempotent conversion.
POST /notifications/:id/read persists recipient read marker. GET /reports?days=30 returns financial/attendance aggregate + CSV via ?format=csv&type=students|financial|attendance. CSV escapes formula injection.
GET/PATCH /settings -> {settings,version}; root handles versioned validated settings, files /assets via multipart and GET /assets/:id. GET/PATCH /users; role changes super_admin only, admin may create non-admin accounts; last owner cannot be removed; session invalidation on role/pass/deactivate. Root handles.

## Persistence/business invariants
Schema with foreign keys, indexes, status enums checked in Zod, nonnegative cents and quantities. D1 batch atomic statements; atomic guarded updates/triggers for concurrent money/stock/capacity; no read-then-write transaction gap. UI waits for actual API success, errors retain input. Never fake successful mutations or metrics. Record audit on every mutation; critical operation audit participates in same batch where possible. Settings may include gymName, tagline, font ('manrope'|'inter'|'system'), sidebarPosition ('left'|'right'), iconStyle ('outline'|'solid'), iconOverrides map finite library names, accentColor, backgroundColor, logoAssetId, wallpaperAssetId, wallpaperOpacity 0..0.35, accessGraceDays 0..30. Secure upload PNG/JPEG/WebP only, <=5 MB, magic byte validation, R2 assets; never arbitrary CSS/HTML/JS. Shared permission enum in server/auth.ts.

## Backend hardening 1.1.0

`GET /api/health` and `HEAD /api/health` check required database schema; unsupported methods return 405. `GET /api/system/readiness` requires super_admin and reports configuration checks (200 ready, 503 incomplete), without credentials. Every API response includes `X-Request-ID`; JSON errors include the same identifier; 429 includes Retry-After. Session idle timeout is 30 minutes, absolute timeout remains 12 hours. TOTP counters are consumed transactionally once. Existing UI payload shapes remain compatible.
